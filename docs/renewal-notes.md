# 첫 수익 이후의 개편 노트

## 출발점

처음 앱을 만들 때는 기능을 완성하고 출시하는 것에 집중했습니다. 시간이 지난 뒤 처음 수익이 발생한 것을 확인하면서, 누군가 선택한 앱의 다음 버전을 어떻게 만들어야 할지 다시 생각하게 됐습니다.

이번 작업에서는 기능의 개수보다 기록의 흐름을 중심에 뒀습니다. 입력한 값이 어디에 합산되는지, 영수증이 어느 거래에 연결되는지, 백업을 되돌릴 때 기존 자료가 어떻게 보존되는지부터 점검했습니다.

## 1. 기록의 기준부터 맞추기

월을 바꾸거나 사업장을 구분해도 홈과 목록, 보고서가 같은 기준으로 계산되도록 정리했습니다. 사진 개수만으로 모든 비용의 증빙 상태를 판단하거나, 입력이 부족한데도 단정적인 분석을 보여 주는 표현도 정리했습니다.

세금과 관련된 숫자는 참고 범위와 사용자 입력의 의미를 설명하도록 바꿨습니다. 저축 목표와 실제 납부 세액이 혼동되지 않게 하는 것도 이 작업에 포함했습니다.

## 2. 입력하고 돌아오는 흐름 다듬기

비용을 추가하려고 들어갔을 때 비용 입력부터 시작하고, 저장한 뒤에는 진입했던 흐름으로 돌아가도록 점검했습니다. 검색·필터·거래 복제와 반복 예정 기록을 추가해 같은 작업을 줄였습니다.

거래와 영수증을 연결하고, 아직 정리하지 않은 사진이나 증빙이 필요한 기록을 따로 확인할 수 있도록 구성했습니다. 문자 인식 결과는 자동 확정하는 대신 사용자가 확인한 뒤 적용합니다.

## 3. 경계가 보이는 화면 만들기

배경색만으로 구분하던 카드와 버튼에 테두리와 면 색 차이를 더했습니다. 입력창과 선택 상자, 현재 선택한 탭도 서로 구분되도록 정리했습니다.

라이트·다크 테마에서 대비를 확인하고, 큰 글꼴과 화면 회전 상황도 검증했습니다. 보기 좋은 화면뿐 아니라 어디를 누르고 무엇을 입력하는지 바로 알 수 있는 화면을 목표로 했습니다.

## 4. 기록을 보관하고 되돌리는 과정 보강하기

백업에 사진까지 포함하고, 필요하면 암호화하도록 구성했습니다. 복원은 파일을 읽자마자 현재 기록을 덮어쓰는 대신 검사와 미리보기, 병합·교체 선택을 거치도록 했습니다.

CSV는 열을 연결하고 중복 기록을 확인한 뒤 가져오도록 보완했습니다. 월말 자료를 PDF나 이미지 등으로 꺼내는 흐름도 함께 점검했습니다.

## 5. 바뀐 앱과 설명을 일치시키기

소개 문구와 시각 자료도 실제 제공하는 기능을 기준으로 새로 정리했습니다. 지원하지 않는 기능을 크게 약속하기보다, 사용자가 무엇을 기록하고 어떤 자료를 저장할 수 있는지 설명하는 데 집중했습니다.

## 남기고 싶은 점

첫 수익이 이번 작업을 시작하게 했지만, 개편의 기준은 수익 숫자가 아니라 사용자가 맡기는 기록이었습니다. 기능을 추가하는 것만큼, 기존 동작을 다시 읽고 틀릴 수 있는 지점을 줄이는 일이 필요했습니다.

이 문서는 실제 앱을 특정할 수 있는 정보와 운영 구현을 제외한 공개 기록입니다.
